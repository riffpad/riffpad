# Riffpad 产品需求文档（PRD）

> 版本：v0.1（2026-08-04）
> 产品：AI coding agent 的移动遥控器
> 关联文档：[TSD](tsd.md)、[设计总览](design.md)

---

## 1. 背景与定位

### 1.1 背景与痛点

AI coding CLI（Claude Code、Codex、DeepSeek CLI、Kimi CLI 等）已经从“回答问题”进化到“长时间自主执行任务”。用户把任务交给 agent 后，仍需要守在电脑前：

- agent 中途等待审批时，人不在就卡住
- 长任务（测试、重构、多文件修改）无法在地铁、床上、通勤路上查看进度
- 多会话并行时难以追踪哪个 agent 卡住、哪个已完成
- 想“换一个方向”或追加指令，必须回到电脑前

现有方案均有明显缺口：

| 方案 | 缺口 |
|---|---|
| 官方移动端（如 Claude Code mobile） | 仅覆盖自家 CLI；会话跑在厂商云端，不是用户自己的电脑 |
| SSH / Mosh / Tailscale + tmux | 配置繁琐；裸 TUI；无 AI 感知，不知道 agent 在等审批 |
| 通用终端镜像（pmux / TermBridge 等） | 只解决“看”，不解决“审批、转向、结构化事件” |
| 开源伴生 app | 大多 iOS 先行、英文、单工具，国内 CLI 用户无产品可用 |

### 1.2 产品定位

Riffpad 不是一个新的 AI coding 工具，而是**已有 AI coding agent 的“手机遥控器 + 陪伴层”**：

- **不替代**：agent 继续跑在用户自己的电脑上，用自己的 API key、自己的仓库、自己的工具链
- **跨 CLI 通用**：Claude Code、Codex、DeepSeek CLI、Kimi CLI……一个 app 全管
- **监督**：手机上实时查看进度、工具调用、文件变更
- **审批**：agent 等待确认时推送通知，手机一键同意 / 拒绝 / 修改条件
- **转向**：语音或文字远程下达新指令
- **隐私**：云端只做加密中继，不落盘、不解密；用户的数据留在自己电脑上

一句话定位：**“你的 AI 在等你审批时，它会在你口袋里叫你。”**

### 1.3 它不是什么

- 不是云端 IDE / 云沙箱
- 不是通用远程桌面 / 远程终端模拟器
- 不是 SSH 客户端
- 不是新的 AI coding agent

## 2. 用户画像与典型场景

| 用户类型 | 核心痛点 | 典型场景 |
|---|---|---|
| 独立开发者 / 全栈工程师 | 长任务和多会话需要持续盯着 | 睡前丢一个重构任务给 Claude Code，躺床上看进度，卡住时手机批准 |
| AI CLI 重度用户 | agent 等待审批时人不在 | 地铁上收到“可以删除文件吗”推送，一键拒绝并输入新条件 |
| 国内 AI 用户（DeepSeek / Kimi / GLM） | 无官方移动伴侣，安卓无产品 | 手机上看 DeepSeek CLI 跑数据任务，语音说“改用 CSV 输出” |
| 创业者 / 技术负责人 | 想随时掌握团队或自己的 agent 状态 | 会议间隙瞄一眼进度，回家路上处理审批 |

## 3. 功能需求

优先级：P0 = MVP 必须；P1 = 第一期增强；P2 = 后续。

### 3.1 设备接入与配对（P0）

- daemon 一键安装到 macOS / Linux，启动后显示二维码
- 手机 app 扫码配对，完成密钥交换；支持多手机、多电脑
- 支持撤销已配对设备；daemon 可一键熔断所有连接

### 3.2 实时监控（P0）

- 结构化事件流：agent 状态（运行中 / 等待输入 / 完成 / 出错）、工具调用、文件变更、命令执行
- 无结构化输出时的兜底：终端视图（xterm.js 渲染）
- 会话列表：多会话并行，状态一目了然
- 历史回放（P1）：离线查看本次会话的事件时间线

### 3.3 审批与遥控（P0）

- agent 等待审批时推送通知，手机查看操作摘要
- 一键同意 / 拒绝 / 修改条件后同意
- 暂停、继续、停止当前会话
- 文字指令远程注入；语音转文字指令（P1）

### 3.4 通知（P0）

- 关键事件推送：等待审批、任务完成、出错、会话失联
- 免打扰时段与按会话静音（P1）
- MVP 用 Web Push；国内生产环境接安卓厂商推送（华为 / 小米 / OPPO / vivo）（P1）

### 3.5 隐私与安全（P0）

- 传输端到端加密，中继无解密能力、不持久化内容
- 移动端默认只读，远程指令是显式用户动作
- daemon 不收集、不存储 API key 明文
- 设备丢失可远程撤销

### 3.6 会话分享（P2）

- 生成只读分享链接，实时同步会话进度
- 适用场景：结对调试、教学演示、团队围观

### 3.7 CLI 支持路线

| 阶段 | 支持对象 | 方式 |
|---|---|---|
| P0 | Claude Code、Codex | 官方结构化输出模式（stream-json / JSON 事件） |
| P1 | DeepSeek CLI、Kimi CLI、GLM 等 | 结构化输出 + 适配器 |
| P2 | 任意终端 / tmux 会话 | PTY / tmux 控制模式兜底 |

## 4. 非功能性需求

| 项 | 要求 |
|---|---|
| 移动优先 | 所有核心操作（查看、审批、转向）在手机竖屏可完成 |
| 事件延迟 | 国内网络环境下事件到手机 < 500ms（P95） |
| 推送延迟 | 审批类通知到达 < 5s |
| 资源占用 | daemon 常驻内存 < 50MB，空闲时近零 CPU |
| 隐私 | 中继零知识；内容不落盘；可自部署中继（P2） |
| 成本 | 中继按带宽计费，免费层 1 台设备 / 2 个并发会话 |

---

## 5. 关键指标（KPI）

1. **安装 → 配对转化率**：> 60%
2. **审批闭环率**：收到推送后 30s 内响应的比例 > 50%
3. **7 日留存**：> 25%
4. **免费 → Pro 转化**：> 5%
5. **会话恢复率**：daemon 重启后会话可恢复 > 95%

| 里程碑 | 内容 | 验收 |
|---|---|---|
| M0（2 周） | 验证闭环：Claude Code 适配器 + 事件到手机 + 审批按钮 | 真实用户能在地铁完成一次审批 |

| M3（后续） | 会话分享、任意 tmux 兜底、团队版 | 分享链接可用，付费转化验证 |
